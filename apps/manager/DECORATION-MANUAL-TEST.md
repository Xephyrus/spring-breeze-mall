# 装修面板改造 —— 手测流程（第二批：7 个面板）

> 适用范围：`PanelTopBar` / `PanelVideo` / `PanelRecommendFeed` / `PanelCarousel` /
> `PanelTitle` / `PanelArticle` / `PanelNotice` 的 `props.options` → `emit("update:options")` 改造。
> 目标：确认**配置能改、能存、能回显、无 props 警告、无死循环**。

---

## 3. 落盘验证（关键，5 分钟）

这一节是**判断改造是否成功的核心**，不是看界面，是看请求内容。

1. 打开 Network，过滤 `update`（保存接口是 `PUT /other/pageData/update/{id}`）；
2. 在 2.1 里改一个字段（例如欢迎文案改成 `落盘验证A`），点「保存」；
3. 点开该请求 → **Payload / Request Body** → 找到 `pageData` 字段；
   - 它是 JSON 字符串，可以先复制出来，用格式化工具展开；
   - 在 `list → [组件] → options` 里搜索 `落盘验证A`；
4. **期望**：能搜到 `"welcomeText": "落盘验证A"`（而不是 `{}` 或旧值）；
5. 按 F5 刷新 → 重新打开该页面 → 欢迎文案仍是 `落盘验证A`；
6. 再点一次保存（不做任何修改）→ payload 里该字段仍在（**不会被默认值覆盖或清空**）。

> 如果第 3 步搜不到，说明 `emit("update:options")` 没把数据合并进 `comp.options`，
> 这是本次改造最需要盯的点。

## 4. 老数据兼容验证（3 分钟）

用 0.3 找到的那个「options 字段很少」的老页面：

1. 打开它 → 对应组件的面板应显示**默认值**（例如顶部栏显示「欢迎来到商城」）；
2. **不要改任何东西**，直接点保存；
3. 看 payload：
   - `options` 里应**补齐默认字段**（`welcomeText`、`loginText`…）；
   - 老页面原有的其它字段**不能被清掉**；
4. 刷新后该页面顶部栏显示正常（不出现空白文案）。

> 这一步验证的是 `onMounted` 首次同步逻辑——没有它，默认值不会落库，
> 保存后刷新会丢默认文案。

## 6. 失败对照表

| 症状 | 最可能原因 | 请提供 |
|---|---|---|
| 改了字段，画布不变 | 面板没走 `local`（vendor 缓存/热更新未生效） | 该面板文件名 + Console 报错 |
| 画布变了，保存后刷新丢失 | `emit("update:options")` 未送达父组件 | 保存请求 payload 截图 |
| 保存 payload 里 options 是 `{}` | `config-panel/index.vue` 的 `applyComponentOptions` 未生效 | Console 里 `Vue warn` 全文 |
| 老页面打开后文案空白 | `onMounted` 首次同步缺失 | 该页面 `GET /other/pageData/{id}` 响应 |
| Console 出现 `Avoid mutating a prop` | 该面板仍有 `props.options.x =` 残留 | 警告的组件名 + 行号 |
| 保存按钮一直转圈 | 出现死循环（`watch` ↔ props） | Performance 截图 |

## 7. 需要重点留意的三个面板

按改造复杂度排序，这三处风险最高：

1. **`PanelArticle`** —— 正文是较长 HTML，验证「保存后内容完整」（注意 payload 是否被截断）；
2. **`PanelNotice`** —— 条目数组增删排序，验证「保存后顺序一致」；
3. **`PanelCarousel`** —— 幻灯片数组 + 多个枚举字段，验证「枚举值保存后不变默认值」。
